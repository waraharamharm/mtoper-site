# mtoper.ru

Внутренний набор сервисов для операторов смены Московского транспорта.

| | |
|---|---|
| **Адрес** | https://mtoper.ru |
| **Для кого** | Операторы и супервайзеры смены |
| **Доступ** | Только после входа; не публичный сайт для граждан |

---

## Назначение

Один вход на сайт и три рабочих инструмента смены:

1. **Справочник ситуаций** (`/handbook/`) — подсказки по нестандартным обращениям и связке с базой знаний.
2. **Перерыв и обед** (`/breaks/`) — запись на слоты перерыва / обеда / био.
3. **Портал оператора** (`/operator/`) — реестр муниципальных маршрутов, учебный «Забота», памятка СТО.

Цель — ускорить работу на смене без разрозненных таблиц и внешних приложений.

---

## Архитектура

```
Браузер ── HTTPS ──► nginx (mtoper.ru)
                        │  проверка сессии (auth_request)
                        ├── /              → portal     :3002
                        ├── /handbook/     → situations :3000
                        ├── /breaks/       → breaks     :3001
                        └── /operator/     → operator   :3004
```

| Слой | Как устроено |
|------|----------------|
| Прокси | Nginx: TLS, HSTS, CSP, единый вход |
| Приложения | Node.js (Express), PM2, слушание только `127.0.0.1` |
| Сессия | Общая cookie `mtoper_session` (HMAC), revoke/lockout в общем SQLite |
| Данные | Локальные SQLite на сервере |
| Статика | Локальные шрифты Manrope, без внешних CDN |

Общая библиотека `@mtoper/session`: подпись сессии, rate limit, lockout, санитизация HTML, заголовки безопасности, `X-Request-Id`.

---

## Доступ

- Вход служебными учётками **оператора** и **супервайзера** (не персональные аккаунты сотрудников).
- Cookie: `httpOnly`, `Secure`, `SameSite=Strict`.
- Рабочие разделы и API приложений требуют валидную сессию (в т.ч. на уровне Node, не только nginx).
- Запись на перерыв доступна только после входа на сайт; браузерный токен лишь разделяет «мои» брони на общем ПК.
- Health-проверки отвечают только с localhost.

| Роль | Возможности |
|------|-------------|
| Оператор | Справочник, перерывы, портал оператора |
| Супервайзер | То же + управление слотами в перерывах |

---

## Данные и конфиденциальность

Система **не ведёт кадровый или клиентский реестр**:

- нет справочника ФИО сотрудников;
- нет личных e-mail и персональных кабинетов;
- учебный «Забота» хранит практику только на нашем сервере и не отправляет заявки во внешнюю боевую систему;
- паспортные и платёжные данные граждан не собираются.

Технические следы, необходимые для работы веб-сервиса:

| Что | Зачем |
|-----|--------|
| Cookie сессии | Проверка входа |
| Анонимный client-token в браузере | Разделение броней/учебных заявок на общем компьютере |
| Факт бронирования слота | Очередь перерывов |
| Служебные логи (IP, request-id) | Диагностика; при неудачном входе логин не пишется |

## Надёжность и сопровождение

- Ежедневный бэкап SQLite в `/var/backups/mtoper/` с ротацией 7 дней.
- Общий файл revoke/lockout: `/var/lib/mtoper/session-store.sqlite` (обязателен в production).
- CI: автотесты приложений и пакета сессии, `npm audit` (high).
- Секреты и пароли не хранятся в git.

Пример env для PM2: `SESSION_SECRET`, `SITE_PASSWORD`, `SV_SITE_PASSWORD`, `SESSION_REVOKE_FILE`.

---

## Ограничения

1. Общий пароль смены удобен, но его нужно менять при утечке и не публиковать в открытых чатах.
2. На общем ПК после смены стоит выйти из аккаунта.
3. В учебный «Забота» не следует вносить реальные данные заявителей.
4. Юридическая оценка обработки данных при необходимости согласуется с ответственным за ИБ / юристом организации.
